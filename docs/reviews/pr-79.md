## Findings against my own branch

### Open (not fixed on the branch)

#### S-1 · A host with only a Python engine cannot launch (pre-existing)

`src/daemon/mod.rs` (`with_launch_env` under `if let Some(binary) = opts.binary`), `src/daemon/launch_service.rs:313`

`LaunchEnv` is built only when the default `llama-server` resolves, and `compose_and_spawn` refuses without it. The first spark2 launch failed with "daemon launch environment not configured" until `LLAMASTASH_LLAMA_SERVER` pointed at an unrelated llama-server. vLLM has the same gap. Filed in TODO.md; the fix is generic (let a process-per-model backend's own launcher satisfy the environment) and out of this PR's scope.

#### S-1b · `resolved_ctx` is empty on an SGLang launch without `--ctx`

`src/backend/sglang/mod.rs::fetch_actuals`

`/get_server_info` reports `context_length: null` when `--context-length` was not passed (measured on 0.5.18); the actuals read nothing else. Filed in TODO.md with the catalog row's `max_position_embeddings` as the fallback.

#### S-2 · Identity is minted by whichever safetensors engine claims the path first

`src/backend/mod.rs::synthetic_identity_for_path_available`

With both engines on, vLLM (registered first) claims every safetensors directory, so `ModelIdentity::Backend { backend: "vllm", name }` is what gets persisted even for a `--backend sglang` launch; `resolved_backend` records the real engine separately and the running row reports it correctly. Both engines derive the same `name`, so keys stay consistent. Cosmetic today; worth a note if `identity.backend` ever drives routing.

#### S-3 · Hybrid models are priced as full attention

`guard::kv_bytes_per_token_from`

Nemotron-H / Qwen3-Next style repos get a cap smaller than they could take. Safe direction, and TODO.md lists reading `layer_types` once one is measured.

#### S-4 · SGLang's `model`-field validation — pinned, no action

Measured 2026-09-09: an unregistered `model` name is served (200) on 0.5.18, so no alias registration is needed. `uat.sh chat` now asserts that; if a future release starts validating, the stage fails with the reason.

### Fixed during the branch (recorded so the reviewer sees them)

- `served-model-name` was a declared knob and also always set by the launcher: two occurrences, argparse keeps the last, readiness waits for the first. Removed from the table and refused in extras (`a_served_name_in_extras_is_stripped`).
- `quantization` clashed with vLLM's kind (`registry_is_valid`); `tool-call-parser` / `reasoning-parser` had empty choice lists that panicked `every_declared_knob_reaches_every_surface`. Now the vLLM shape and closed `Enum`s respectively; `shared_ids_are_the_expected_set` pinned with the two new shared ids.
- `--enable-unified-memory`'s help text was wrong (it is a hybrid-pool layout switch, not host UMA) — fixed, and the casebook entry that had the same misreading is corrected.
- Two safetensors projectors for one snapshot collapsed to one row with one backend (catalog keyed by path). `merge_by_path` + a daemon-driven test.
