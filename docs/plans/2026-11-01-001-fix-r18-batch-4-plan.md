# fix: R18 batch 4, three small standalone fixes

## Goal

Close the three `TODO.md` items under `## R18 (v0.11.0 checklist)` → `### Batch 4: small standalone fixes`. Each one shows the user a number or a flag that is not the one they got.

## Scope

In: the three items below, their tests, `TODO.md` strikes, one `CHANGELOG.md` `[Unreleased]` line per user-visible fix, docs that the change makes wrong.

Out: forwarding a dropped knob to the engine as a raw flag; fetching HF file sizes for recommended rows; any change to the recommender's ranking or fit math.

## Decisions

- **U1, mark estimates, do not fetch.** A recommended row whose catalog entry has `gguf_publisher == "synthetic"` has an estimated `weights_bytes` (the Q3_K_M Qwen3-4B row says 1,759,829,792 bytes; the real file is about 2 GB). The row keeps its current numbers but says they are estimates. Reason: no new HF calls, works offline, and the File picker already shows the real size and verdict one `Enter` later. Chosen by the user over writing back the real size or fetching sizes up front.
- **U2, warn only.** The `start` warning for a knob the user set that the resolved backend drops existed before and was lost in `fe27392` ("refactor(knobs): one KnobSet on every launch"); since then the drop is only a `log::info!` in the daemon log (`src/daemon/launch_service.rs`, the `for dropped_id in &resolved.dropped` loop). `docs/usage.md` line ~470 still says the `warnings` array carries dropped knobs, so restoring it makes the docs true again. Forwarding is out: the daemon does not know the spelling the user typed, and an SGLang-only flag forwarded to `llama-server` would make the engine exit at startup. Chosen by the user.
- **U2 warns against the user layer only**, never the resolved set. The resolved set carries model defaults and arch defaults, and warning on those made every launch on a narrow backend noisy (the reason the old code filtered by the user layer).
- **U3, monotonic window start.** `RequestRow` gets a `#[serde(skip)]` monotonic start, set in `RequestLog::begin`. `Throughput::add` / `add_prefill` build their windows from it. `started_at_ms` stays the wall-clock field the wire and the UI show.

## Units

All three are independent and share no files. One lane does them in order U3, U2, U1 (smallest risk first).

### U1. Pull dialog: mark estimated sizes on recommended rows

Files: `src/tui/hf_dialog.rs` (and its golden snapshots under `tests/` / `src/tui/snapshots/` if a rendered row changes), `TODO.md`, `CHANGELOG.md`.

- In `render_recommendation_row`, for a `RecommendationKind::Curated { entry }` with `entry.gguf_publisher == "synthetic"`:
  - size column reads `~<size>` (e.g. `~1.6 GiB`), same column width as now (truncate if needed, keep alignment).
  - the fit cell keeps the glyph but the word gets a `~` prefix too (`✓ ~fits`, `⚠ ~tight`, `✗ ~oversize`), so the verdict reads as an estimate. The `spill ~N%` branch is unchanged.
  - Non-synthetic rows render exactly as today.
- Extend `RECOMMENDATIONS_NOTE` (or the line rendered under it, whichever the layout allows without wrapping changes on the 160x45 render) with one plain sentence: `~` sizes are estimates; the file list shows each file's real size and fit.
- Delete the `TODO:` doc comment above `render_recommendation_row` that points at this item.
- Test: a unit test in `hf_dialog.rs` renders one synthetic and one non-synthetic recommendation row with a 4 GiB `HardwareFitContext` (the existing test helpers near line ~2197 build one) and asserts the `~` appears on the synthetic row's size and fit word only. Regenerate any golden snapshot the change touches and check the diff is only the new `~` / note text.
- Depends on: nothing.

### U2. `start` warns about a user knob the backend drops

Files: `src/daemon/launch_service.rs`, a test (inline `#[cfg(test)]` in `launch_service.rs` if the compose path is reachable there, else the integration test that already asserts `start` `warnings`: find it with `rg -n '"warnings"' tests/`), `TODO.md`, `CHANGELOG.md`.

- In `compose_and_spawn` (where `resolved.dropped` is logged), for each id in `resolved.dropped` that the **user layer** (`user_knobs`) set, push one warning onto the launch's `warnings` vec, e.g. `` vllm does not take the `reasoning-parser` knob; it was not passed to the engine. Put the flag in a preset's `extras:` to pass it as-is. `` Build the backend name from `resolved_backend_id` / `backend.id()`, never a literal (backend no-leak rule in `AGENTS.md`). Keep the existing `log::info!`. One warning listing all dropped ids is fine if that reads better; pick one and keep it short.
- `warnings` is declared after the drop loop today; move the declaration up or collect the dropped user ids first and push them once `warnings` exists. Do not change how warnings reach the CLI (`copy_warnings` in `src/cli/start.rs`) or the TUI.
- Test: a launch whose user layer sets a knob only another backend declares returns that knob in `warnings`; a launch where only a default/preset layer supplies it returns no such warning. The fake engine in `tests/fixtures/` serves llama.cpp, so use a knob llama.cpp does not declare but another backend does (the `reasoning-parser` SGLang knob works if llama.cpp does not declare it; check `src/backend/*/knobs.rs`).
- `docs/usage.md` already says the `warnings` array carries dropped knobs: re-read that paragraph and the `start` section, fix wording only if it is now wrong.
- Depends on: nothing.

### U3. Request log windows on a monotonic clock

Files: `src/proxy/request_log.rs`, `TODO.md`, `CHANGELOG.md`.

- Add to `RequestRow` a field such as `#[serde(skip)] pub(crate) started_mono_ms: Option<u64>`: milliseconds since a process-wide monotonic origin (`static ORIGIN: OnceLock<Instant>`, or an existing one in `crate::util` if there is one; grep first). Set it in `RequestLog::begin` next to `started_at_ms`.
- `Throughput::add` and `add_prefill` anchor windows on `row.started_mono_ms.unwrap_or(row.started_at_ms)`. The fallback only fires for rows not made by `begin` (unit tests, a deserialized row), which never mix with `begin` rows in one ring; say so in a one-line comment.
- `RequestRow` derives `PartialEq`; a test that compares a `begin` row with a deserialized copy would now differ on the skipped field. Fix such tests by comparing without it, or exclude the field from equality with a manual impl only if many tests break. Keep the wire shape byte-identical (the field never serializes; the test that lists the wire keys near line ~3403 must still pass unchanged).
- Update the `Throughput.windows` doc comment (`on the rows' own clock`) to say which clock.
- Test: two finished rows whose `started_at_ms` are an hour apart (a simulated clock step) but whose `started_mono_ms` are back to back give the same `busy_ms` / aggregate tok/s as two rows with consistent clocks.
- Depends on: nothing.
